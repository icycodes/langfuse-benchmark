# Versioned Chat Prompt with Labels (Langfuse Python SDK) ## Background You are setting up https://langfuse.com/ prompt management for a movie review assistant. The team wants to keep an actively-tested `staging` version of the prompt alongside the currently-deployed `production` version, so engineers can iterate safely. Your job is to use the **Langfuse Python SDK** to programmatically register two versions of a chat prompt and attach the correct labels, so the application can fetch each version by label at runtime. The environment already has the `langfuse` Python SDK installed and the following environment variables exported: `LANGFUSE_PUBLIC_KEY`, `LANGFUSE_SECRET_KEY`, and `LANGFUSE_BASE_URL`. The `ZEALT_RUN_ID` environment variable contains a unique run identifier you **must** use when naming the Langfuse prompt to avoid conflicts with concurrent task runs. ## Requirements * Write a Python script `create_prompts.py` that uses the Langfuse Python SDK (`from langfuse import Langfuse` or `from langfuse import get_client`) to create a single chat prompt with two versions in your Langfuse project. * The prompt **name** must be `movie-critic-chat-${ZEALT_RUN_ID}` (read `ZEALT_RUN_ID` from the environment). * Both versions must be created as `chat` prompts (a list of role/content message dicts) and must use Langfuse template variables (double-curly-brace syntax). * Version 1 (created first) is a baseline prompt that must be labeled `staging`. * Version 2 (created second) is an enhanced prompt that must be labeled `production` (this becomes the default version served when no label is specified). * Execute the script so that both prompt versions are actually created on the Langfuse server. * Write a log file at `/home/user/langfuse_task/output.log` summarising the result. ## Implementation Hints * Initialise the SDK without hardcoding credentials; the client reads `LANGFUSE_PUBLIC_KEY`, `LANGFUSE_SECRET_KEY`, and `LANGFUSE_BASE_URL` from the environment. * Use the SDK's `create_prompt` method with `type="chat"` and a `prompt` payload that is a list of `{"role": ..., "content": ...}` dicts. * Use the `labels` parameter of `create_prompt` to attach labels at creation time.
